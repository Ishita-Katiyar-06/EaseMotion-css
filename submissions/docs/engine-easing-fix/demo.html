Bug Fix: ease-in-out Easing Value

In easemotion/engine/parser.js, the 'ease-in-out' key was mapped to cubic-bezier(0.4, 0, 0.2, 1) — the exact same value as the default 'ease' curve. This made both tokens visually identical, defeating the purpose of specifying ease-in-out in an em="" attribute.

❌ Before (Buggy)

cubic-bezier(0.4, 0, 0.2, 1)  ← same as 'ease'

EASE
const EASING_MAP = { 'ease': 'cubic-bezier(0.4, 0, 0.2, 1)', 'ease-in-out': 'cubic-bezier(0.4, 0, 0.2, 1)', // ← BUG: same as ease };

✅ After (Fixed)

cubic-bezier(0.42, 0, 0.58, 1)  ← symmetric ease-in-out

EIO
const EASING_MAP = { 'ease': 'cubic-bezier(0.4, 0, 0.2, 1)', 'ease-in-out': 'cubic-bezier(0.42, 0, 0.58, 1)', // ← FIX: symmetric };

📋 Proposed Fix — easemotion/engine/parser.js

/** Canonical easing aliases → CSS values */ const EASING_MAP = { 'ease': 'cubic-bezier(0.4, 0, 0.2, 1)', 'ease-in': 'cubic-bezier(0.4, 0, 1, 1)', 'ease-out': 'cubic-bezier(0, 0, 0.2, 1)', 'ease-in-out': 'cubic-bezier(0.4, 0, 0.2, 1)', // BUG: duplicate of 'ease' 'ease-in-out': 'cubic-bezier(0.42, 0, 0.58, 1)', // FIX: standard symmetric ease-in-out 'linear': 'linear', 'spring': 'cubic-bezier(0.34, 1.56, 0.64, 1)', 'bounce': 'cubic-bezier(0.34, 1.56, 0.64, 1)', 'snap': 'cubic-bezier(0.77, 0, 0.175, 1)', };
